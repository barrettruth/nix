# AeroSpace snippets

Use the installed command's `--help` when a flag differs. These snippets avoid
window titles unless a title is necessary to answer the question.

## Installation and active configuration

```sh
aerospace --version
aerospace config --config-path
aerospace reload-config --dry-run --no-gui
```

The version command reports both client and app-server versions. A mismatch can
explain missing commands or unexpected parsing. The config path is generated by
nix-darwin on this setup; inspect the returned file and edit the corresponding
Nix source instead.

Use `--warnings-as-errors` when warnings must produce a non-zero status:

```sh
aerospace reload-config --dry-run --no-gui --warnings-as-errors
```

## Compact live inventory

```sh
aerospace list-monitors --format \
  '%{monitor-id} %{monitor-name} %{monitor-is-main}' --json

aerospace list-workspaces --all --format \
  '%{workspace} %{workspace-is-focused} %{workspace-is-visible} %{workspace-root-container-layout} %{monitor-id}' \
  --json

aerospace list-windows --all --format \
  '%{window-id} %{app-bundle-id} %{workspace} %{window-layout} %{window-is-fullscreen} %{workspace-root-container-layout} %{monitor-id}' \
  --json
```

Use `--monitor focused` or `--workspace visible` instead of `--all` when the
problem is local to what the user can currently see.

## Why are Chrome tabs or windows overlapping on workspace 2?

First determine what AeroSpace actually manages:

```sh
aerospace list-windows --workspace 2 --format \
  '%{window-id} %{app-bundle-id} %{workspace} %{window-layout} %{window-is-fullscreen} %{workspace-root-container-layout}' \
  --json
```

Interpret the result before proposing a change:

- One Chrome window means AeroSpace sees one top-level window. Chrome tabs are
  internal to that window and AeroSpace cannot arrange them.
- `floating` windows may overlap by design.
- `h_accordion` or `v_accordion` intentionally stacks windows with an exposed
  edge. Either the immediate parent or workspace root can be accordion.
- A fullscreen window covers its workspace until fullscreen is disabled.
- Several tiled windows with no visible accordion ancestor point to a more
  unusual tree or Accessibility API problem. Do not use `debug-windows` unless
  the user is gathering an upstream bug report; its output is unstable.

When the user asks for the corresponding live correction, target the known
window or workspace:

```sh
aerospace layout --window-id <window-id> tiling
aerospace fullscreen off --window-id <window-id>
aerospace layout --workspace 2 --root tiles
aerospace balance-sizes --workspace 2
```

Resetting the whole workspace discards its nested arrangement, so use this only
when the user explicitly asks for a reset:

```sh
aerospace flatten-workspace-tree --workspace 2
aerospace layout --workspace 2 --root tiles horizontal
aerospace balance-sizes --workspace 2
```

## An app opened on the wrong workspace

Find the bundle ID and the window's actual workspace without relying on its
title:

```sh
aerospace list-apps --format '%{app-pid} %{app-bundle-id} %{app-name}' --json

aerospace list-windows --all --format \
  '%{window-id} %{app-bundle-id} %{workspace} %{window-layout}' --json
```

Then inspect, in order:

1. The app's `bundleId` and `space` in `barrett.mac.apps`.
2. Whether the host extends or overrides the shared app list.
3. The generated `on-window-detected` order.
4. Whether an earlier floating rule matches the same bundle ID and stops later
   processing.
5. Whether a title-based rule is racing the title's initialization.

For a one-time move of a known window:

```sh
aerospace move-node-to-workspace --window-id <window-id> <workspace>
```

For persistent routing, change the Nix app declaration or callback rather than
moving the current window and treating that as configuration.

## Inspect one focused window

```sh
aerospace list-windows --focused --format \
  '%{window-id} %{app-bundle-id} %{workspace} %{window-layout} %{window-is-fullscreen} %{workspace-root-container-layout} %{monitor-id}' \
  --json
```

No focused window is a valid state; this command reports an error in that case.

## Workspace navigation and targeted movement

```sh
aerospace workspace <workspace>
aerospace workspace-back-and-forth
aerospace focus --window-id <window-id>
aerospace move-node-to-workspace --window-id <window-id> <workspace>
aerospace move-node-to-monitor --window-id <window-id> <monitor-pattern>
```

Omitting `--window-id` makes movement depend on current focus. Use that only
when the user's request explicitly concerns the focused window.

## Find a binding or persistent setting

From `~/.config/nix`:

```sh
rg -n 'services\.(aerospace|skhd)|barrett\.mac\.(apps|floatingApps)' \
  modules/darwin/barrett/workstation.nix hosts
```

Read `/etc/skhdrc` only as rendered state. Put binding changes in
`services.skhd.skhdConfig`; put AeroSpace settings and callbacks in
`services.aerospace.settings`.
